# Movement coordination

The movement-coordination route accepts only a valid movementNeedId. The activation card's existing backend-activated-only callback now leads here. Direct navigation does not grant access: every entry and foreground resume reloads the authenticated get_post_activation_people contract. No rows means the same unavailable message for missing, unauthorized and nonactivated movements. No masked discovery, private table reads, local activation flags or reconstructed identities are used.

Migration 0014 checks payment success, matching alignment/journey state and actual confirmed participants. Offering members receive confirmed primary/invited travellers. Travellers receive only the offering member. The UI trusts this SQL roster authority; its role validation is defense against malformed responses, not a replacement participant check. Declined/removed/unconfirmed people cannot be selected by SQL. SQL regression checks are static locally; remote rollback tests were not executed.

Cards display available first name, derived age, unified Verified, rating and completed movements. Missing name/rating/age are omitted, never fabricated. Private extra fields are projected away. For travellers only, get_post_activation_vehicle supplies the natural description and full plate; offering members do not see redundant vehicle information. No year, capacity, access records, ownership claim, Common Movement Area, raw DOB, phone/email or internal IDs are displayed.

The existing getPostActivationProfilePhoto helper sends the opaque token and ordinary JWT to the authenticated image proxy. Returned JPEG/PNG/WebP bytes are converted with FileReader to an in-memory data URI for React Native Image. This URI contains image bytes, not a Storage location. No signed URL, bucket/key, token log, local file or persistent identity cache is created. Unavailable/expired photos get neutral fallback text. Existing requests may finish after cancellation, but abort/generation checks prevent them publishing into another screen/account. Memory state is cleared on background, blur, logout/account change, refresh and a conservative four-minute display timeout. Refresh issues new authoritative reads; there is no polling.

Chat, meeting-point editing/maps, live location and journey start/end remain unavailable. No home/private location is inferred and no fake action is offered. Existing 0012 mutual principal completion and 0013 roster/capacity protections are untouched. The screen is a coordination foundation, not a working messaging or pickup system. No migration 0018, Edge deployment or provider integration is needed.

Tests: tests/coordination.test.cjs plus all existing regression suites. Device-level visual testing remains required for native image rendering, accessibility and layout; local mocked component tests do not replace it.
