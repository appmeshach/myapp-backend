# Pricing quote foundation (0061)

WE DO NOT CREATE JOURNEYS. The system matches people to independently existing movement.

Trusted geography evidence answers: **What movement geography was proven?**

0061 answers: **Where will an immutable calculated seat price be recorded and what exact evidence must it be bound to?**

A future Pricing Policy v1 engine answers: **What exact deterministic formula converts that evidence into money?**

A future financial proposal issuer answers: **What obligations are proposed to the participants?**

The acceptance/materialization path answers: **When do those obligations become binding?**

0061 does NOT set the actual price curve. No engine, quote writer, client RPC, proposal issuer or acceptance change is included. The quote amount is an opaque input fact whose economic correctness must be established by a separately reviewed trusted engine.

## Objects and columns

One private table, `private.pricing_quotes`, has these 16 columns:

| Columns | Contract |
|---|---|
| `id` | UUID primary key, generated by default |
| `version` | Positive integer, must equal max historical version + 1 for its canonical identity |
| `pricing_geography_evidence_id`, `pricing_geography_evidence_version` | Exact immutable geography reference and version; ID has a foreign key to 0059 |
| `movement_need_id`, `requesting_member_id`, `offering_member_id` | Canonical need and principals copied from that exact geography |
| `offering_movement_intent_id`, `offering_intent_version`, `state_location_reference_id` | Canonical intent and authoritative state anchor copied from that geography |
| `pricing_policy_version` | Required bounded policy provenance token using the 0020/0021 token convention; not an approval registry |
| `currency` | NGN only at launch, consistent with existing NGN launch flows and valid within 0020/0021's currency format |
| `seat_price_minor` | Required nonnegative bigint, preserved exactly, including zero; no rounding or allocation |
| `status` | `current` or `superseded` |
| `created_at` | Required finite timestamp, clock_timestamp default, no earlier than evidence creation and no later than current time |
| `expires_at` | Required finite timestamp, later than creation, future for live use, no later than exact evidence expiry |

The canonical identity is `(movement_need_id, offering_movement_intent_id)`, matching 0059. Changing policy or source does not create a second current quote identity. A unique constraint protects historical versions, and `pricing_quotes_one_current` is a partial unique index on that identity. The primary key and version constraint also create their standard indexes.

There is deliberately no need foreign key, following 0059's history preservation. The exact evidence FK, immutable evidence, and enforced binding comparison transitively anchor intent and state, without extra early FK lock paths. Both member IDs have member FKs. No copied binding is silently repaired or substituted: a future writer must derive it from exact evidence, and direct owner inserts supplying inconsistent copies fail before insertion.

There is no speculative policy schema field. The table schema and policy version identify the present record contract; any additional provenance contract requires review. No route geometry, coordinates, event copies, coefficients, user prose, provider data, or operational/financial IDs are stored.

## Helpers and enforcement

Three private SECURITY DEFINER helpers, each with `SET search_path = ''`:

- `private.assert_pricing_quote_context(private.pricing_quotes)` checks exact bindings, delegates live dependency validation to `private.assert_pricing_geography_evidence(uuid)`, requires supported geography, and validates quote lifecycle/time bounds.
- `private.assert_pricing_quote(uuid)` validates dependencies before locking the quote FOR SHARE, rereads the quote and repeats validation after the wait. Future consumers must call this in the same transaction as relying on the quote.
- `private.protect_pricing_quote()` validates insertion and next version, protects immutable facts, and rejects removal.

Two triggers on the quote table only:

- `protect_pricing_quote`: BEFORE INSERT OR UPDATE, FOR EACH ROW.
- `prevent_pricing_quote_removal`: BEFORE DELETE OR TRUNCATE, FOR EACH STATEMENT. This rejects deletion even when the predicate matches no rows, and prevents empty-table truncation too.

Insertion must be current and valid under the inherited READ COMMITTED requirement. Dependency lock order remains need -> requester endpoints -> intent -> route -> match -> geography -> quote. The need UPDATE lock inherited from 0059 serializes version checks for the canonical identity, including manual inserts. No advisory lock or source-table trigger is added. Validation does not call the quote trigger recursively.

Version 1 starts a history; later inserts must use the next consecutive version. Existing current history must first be explicitly superseded in the same future writer transaction. 0061 does not automatically supersede or allocate versions on a caller's behalf. A future writer must acquire canonical context locks before locking/superseding existing quote rows, follow the documented dependency order and serialize version allocation. Multi-context operations need a reviewed global ordering. This foundation does not introduce a general public writer.

Every factual column is immutable. Only current -> superseded is permitted; even status no-op updates are rejected. A superseded row cannot reopen, mutate or be deleted. Supersession can retire already stale quotes without requiring their source to remain live. Stored `current` does not mean live: time passing or upstream supersession/closure can invalidate a historical quote without rewriting it.

## Scope, support and security

0059 must prove live evidence and exact upstream route/match/current context. A quote additionally requires both its supported flag and a positive corridor distance <=100000 metres. Greater distances may remain valid same-state geography, but cannot back a supported quote. 0061 neither recalculates geography nor interprets geographic events as money.

The tests use a 15000 metre provider route and a 12000 metre pricing corridor. An amount such as 155037 kobo is an opaque fixture value, not a price calculated from either distance. Bigint syntax rejects fractional textual input; PostgreSQL numeric casts may round before reaching a bigint column, so a future writer must validate input before coercion.

RLS is enabled with no policies. PUBLIC, anon and authenticated have no table access. Service role has SELECT only, with no INSERT, UPDATE, DELETE, TRUNCATE, REFERENCES or TRIGGER grant. All three helpers revoke EXECUTE from PUBLIC, anon, authenticated and service_role. Owner-level test setup remains possible through normal enforced triggers. No operational caller exists yet.

No monetary arithmetic is implemented: no distance curve, stage coefficients, diminishing percentages, MFEU, rounding rules, external transport observations, commercial split or downstream allocation. These belong to later explicitly approved policy and financial integration migrations.

0020 still requires exactly `offering_platform_share`, `requester_platform_share`, and `movement_contribution`. 0021 retains `quoted_platform_fee_total_minor`, `quoted_movement_contribution_minor`, its reserved NULL route guard, and its acceptance/materialization contract. 0061 does not map a seat price or movement contribution to an activation fee and does not mutate either financial foundation. The later issuer must separately define per-seat/group semantics, exact integer allocations, rounding and consent.

No writes target geography, routes, matches, needs, availability, offers, alignments, journeys, payments, activation, settlement, completion, auth, proposals, agreements or components.

## Validation

```powershell
node .\supabase\tests\pricing_quote_foundation.test.cjs
node supabase/tests/pricing_quote_foundation.test.cjs --print-rollback | docker exec -i supabase_db_movement-app psql -X -U postgres -d postgres -v ON_ERROR_STOP=1
```

The generated batch requires installed 0060 and no 0061 objects. It installs the migration body inside a single READ COMMITTED outer transaction, creates trusted fixtures under normal constraints, and finishes ROLLBACK. External snapshots compare pre-existing data, schemas, definitions, constraints, indexes, triggers, permissions, RLS, and migration history; absence checks confirm 0061 objects are gone. The SQL fixture file expects transaction-local installation, so run the generator rather than that file alone.

Behavioral probes isolate their own changes with subtransaction rollback. A separate snapshot after fixture creation covers every nonquote public/private/auth/migration-history row, including geography and all financial and operational tables. Expiry probes use short-lived valid evidence and bounded actual elapsed time, without rewriting immutable expiry fields. Actual route and match writers supply replacement fixtures. These single-session tests do not claim two-session concurrency validation of a future quote writer.

Local validation on 2026-09-30: 115 SQL behavioral assertions passed, zero failed; both external rollback checks passed. Focused Node tests passed 17/17, full `node --test` passed 1,221/1,221, and TypeScript passed. 0061 was not persistently installed. No historical migration, application code or existing financial contract was modified.
